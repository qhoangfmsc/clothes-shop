# Project rules

- **Spec → test → code → docs, every time (closed loop).** A module (an entry of `MODULES` in `scripts/modules.mjs`) owns one doc (`docs/`, what the code does), one tech spec (`specs/`, what it is designed to do and why) and one test folder (`tests/<group>/<module>/`). Before you touch a module: `yarn docs:who <file|folder|module>`, read its doc, spec and code (the code wins over the doc — fix the doc first) and say what the module does. Then **update the spec first** (goal, contract, design decisions, vital flows), **write/update the tests** (characterization tests before refactoring existing behaviour, a failing test before a fix), then code, then the doc. A task is **not done** until `yarn quality:check --changed`, `yarn docs:check --changed` and `yarn test` pass. A module with no spec and tests (listed in `scripts/quality-baseline.json`) gets both the first time you touch it and leaves that list; the list only shrinks. Follow `.agent/rules/quality-loop.md`, `.agent/skills/09-tech-specs.md` and `.agent/skills/10-testing.md`. Tests live in `tests/` only; browser tests run against the real API and are read-only unless `E2E_ALLOW_WRITES=1` is set on purpose. **A module is done only when `yarn test:progress` shows it ✓:** a test matrix covering right and error cases, guest and signed-in, and (for admin) with and without the permission, each flow with a test, and `yarn test:mutants <module>` catching every deliberate break. Existing modules are completed **in batches of at most 5, one batch per session**, then stop: follow `.agent/skills/13-test-process.md` (skill `test-process`; board `yarn test:progress`, plan `scripts/test-batches.json`; principles `specs/_roadmap.md`).
- **Design principles first.** In all new and changed code apply Architecture (module-first, one-way dependencies), Design patterns (only where they remove real duplication or coupling), Coding conventions and SOLID; write each decision and its reason in the spec (section 5, "Quyết định thiết kế"); self-review with `.agent/skills/12-review-checklist.md`. Your final message lists the docs and specs read and updated and the tests added, and ends with a short **"Vì sao"** note (2–6 lines: which pattern or principle you applied, where, and why). The owner is learning these techniques — explain, don't just apply. Follow `.agent/skills/11-design-principles.md`.
- **Docs stay the as-built truth.** `docs/` has one as-built doc per module. Before you touch a module: `yarn docs:who <file|folder|module>`, read its doc and its code (the code wins if they differ — fix the doc first) and say what the module does. After you change it: update that doc in the same change (affected sections + `Cập nhật` date; new module → entry in `MODULES` in `scripts/modules.mjs` + new doc + spec + tests + `docs/README.md` row) and run `yarn docs:check --changed` — a task is **not done** until it passes, and your final message lists the docs you read and updated. Docs hold facts about the code only: no plans, standards or TODOs. Follow `.agent/rules/module-docs.md` and `.agent/skills/07-module-docs.md` (skill `module-docs`).
- **Code in English, UI through i18n.** All source code (identifiers, comments, commit messages) is English. Every piece of user-facing text — labels, buttons, headings, toasts, confirm/error dialogs, placeholders, `aria-label`/`title`/`alt`, page metadata — must come from the message files in `src/messages/<locale>/**` (languages: `vi` default, `en`) via `next-intl`; never hardcode a string in a component, constant or slice, and add every new key to **all** locales. Follow `.agent/skills/04-i18n.md` (also available as the `i18n` skill) for structure, navigation helpers (`@/src/i18n/navigation`) and the `yarn i18n:check` workflow.
- **Lists, errors and toasts are standardized.** List pages follow `.agent/skills/05-list-pages.md` (`buildListQuery`, `DataTable` with search + sort, limit 25 default / 200 max, sort `field` / `-field`); errors and toasts follow `.agent/skills/06-errors-and-toasts.md` (`useErrorMessage`, `toast.created/updated/deleted/saveFailed/deleteFailed`, `useConfirm`). Run `yarn conventions:check` — it also runs before `yarn build`.
- **Responsive on every device class (phone · tablet · iPad landscape · desktop · wide), touch and mouse.** Mobile-first with the Tailwind defaults (`sm 640 · md 768 · lg 1024 · xl 1280 · 2xl 1536`); width decides layout, input decides behaviour (iPads are wide *and* touch); every hover-only feature needs a touch path; no horizontal page scroll. Before you finish a UI change, check it at 390 / 768 / 1024 / 1440 / 1920 and end the report with a one-line `Responsive:` result — or state plainly that no browser was run. Follow `.agent/rules/responsive.md` and `.agent/skills/08-responsive.md` (skill `responsive`).
- **Reuse the shared components.** Any carousel/slider must use `Carousel` (never hand-rolled scroll-snap, touch handlers or dots), admin tables use `DataTable`, and so on — see `.agent/rules/components.md` for the full list and usage rules.

See `.agent/rules/coding.md` for the rest of this project's coding conventions (also followed by other AI tools used on this repo).
