# Đa ngôn ngữ (i18n) — Tóm tắt & hướng dẫn sử dụng

Stack: **next-intl v4** · ngôn ngữ **vi (mặc định) · en** · URL luôn có prefix (`/vi/...`, `/en/...`).

## 1. Cách hoạt động

| Việc | Cách làm |
|---|---|
| Vào URL không prefix (`/shop`) | Tự chuyển về `/vi/shop` (không dò ngôn ngữ trình duyệt) |
| Đổi ngôn ngữ | Nút ở **Footer** và **Burger menu** — giữ nguyên trang + query, chỉ đổi prefix |
| SEO | `<html lang>`, `hreflang` (vi / en / x-default) và `canonical` cho từng trang |
| Giá & ngày | Giá luôn là USD (không quy đổi), chỉ khác cách hiển thị; ngày theo ngôn ngữ |
| Dữ liệu từ API (tên sản phẩm, mô tả…) | Không dịch — BE chưa hỗ trợ đa ngôn ngữ |

## 2. Cây file nội dung (`src/messages/<locale>/`)

```
common.json                 chung toàn app: nút Cancel/Confirm, trạng thái đơn, vai trò, badge, tên ngôn ngữ…
shared/                     dùng ≥ 2 role: header, footer, feedback (toast/dialog/login), errors, cart, site meta
auth/login.json
public/                     landing · about · shop · product · collections · newIn
private/                    account · cart · checkout · orders · wishlist
admin/
  shell.json  dashboard.json  products.json  categories.json  collections.json
  orders.json  users.json  siteConfig.json  media.json
  components/               component admin dùng chung = sub-module riêng
    dataTable.json  formKit.json  imageFields.json  orderDetailPanel.json  guards.json  crud.json
```

Trong mỗi file, nội dung chia nhánh: **page → table → form → modal → toast** (không để phẳng).
Ví dụ `admin/products.json`: `page.*`, `table.columns.*`, `table.filters.*`, `table.sort.*`, `form.tabs.*`, `form.fields.*`, `form.placeholders.*`, `toast.*`, `confirmDelete.*`.

Mỗi role chỉ nhận message của role đó xuống client (`common + shared + auth + public|private|admin`) — khách mua hàng không tải bản dịch admin.

## 3. Quy trình hằng ngày

**Sửa một câu chữ**: sửa đúng key trong `en`, `vi` (cùng key, cùng `{placeholder}`).

**Thêm text mới trong code**
1. Thêm key vào **cả 2** ngôn ngữ, đúng file/nhánh (xem bảng "Text nằm ở đâu" trong `.agent/skills/04-i18n.md`).
2. Dùng trong component:
   ```tsx
   const t = useTranslations("admin.products");
   <h1>{t("page.title")}</h1>
   t("page.count", { count: total })          // số nhiều ICU
   format.number(price, "price")              // tiền
   format.dateTime(new Date(iso), "short")    // ngày
   ```
3. Chạy `yarn i18n:sync` rồi `yarn i18n:check` (hai lệnh này cũng tự chạy trước `dev`/`build`).
4. `npx tsc --noEmit` — gõ sai key là lỗi compile.

**Thêm trang / module mới**: tạo `src/messages/{en,vi}/<role>/<module>.json` (có `meta.title`, `meta.description`), dùng `generateMetadata` + `buildAlternates` + `withBrand`, gọi `setRequestLocale(locale)` ở page/layout server.

**Thêm ngôn ngữ thứ 4, 5 (vd `ja`)**
1. `src/i18n/routing.ts`: thêm `"ja"` vào `locales` và `LOCALE_LABELS` (gồm `ogLocale`, vd `ja_JP`).
2. Copy `src/messages/en` → `src/messages/ja`, dịch.
3. `yarn i18n:check`. Nút đổi ngôn ngữ, hreflang, routing tự nhận — không phải sửa code khác.

## 4. Điều không được làm

- Hardcode chữ trong component / constants / slice (kể cả `aria-label`, `placeholder`, toast, metadata).
- Ghép câu từ nhiều mảnh (`"Sign in to " + action`) — dùng 1 message cho 1 câu.
- `count === 1 ? "item" : "items"`, `toFixed`, `toLocaleString` — dùng ICU plural và `useFormatter`.
- `import Link from "next/link"` hoặc `useRouter/usePathname/redirect` từ `next/navigation` — dùng `@/src/i18n/navigation`.
- Để label trong constants — constants chỉ giữ `key`, component dịch.

## 5. Công cụ kiểm tra

| Lệnh | Việc |
|---|---|
| `yarn i18n:sync` | Sinh lại `src/i18n/registry.ts` từ thư mục `src/messages/en` |
| `yarn i18n:check` | Báo lỗi nếu thiếu file/key, thừa key, giá trị rỗng, lệch `{placeholder}`, registry cũ |
| `npx tsc --noEmit` | Type của message sinh từ JSON `en` → sai key = lỗi |

## 6. SEO, sitemap & robots

Mọi URL công khai đều có prefix ngôn ngữ, nên SEO được dựng quanh danh sách `routing.locales` (một nguồn duy nhất):

| Thành phần | File | Việc làm |
|---|---|---|
| Origin tuyệt đối | `src/lib/site-url.ts` | `SITE_URL` đọc từ `NEXT_PUBLIC_SITE_URL` (production bắt buộc đặt; dev mặc định `http://localhost:3000`). Dùng cho `metadataBase`, sitemap, robots, JSON-LD |
| Canonical + hreflang | `src/i18n/metadata.ts` → `buildAlternates(locale, path)` | Mỗi trang có `canonical` của chính ngôn ngữ đó, `hreflang` cho `vi`, `en` và `x-default` (= `/vi/...`) |
| Tiêu đề | `withBrand(title)` | Dạng `Shop — DOOVAN`; tên thương hiệu không dịch |
| Sitemap | `src/app/sitemap.ts` → `/sitemap.xml` | Mỗi URL xuất hiện **một lần cho mỗi ngôn ngữ**, kèm `alternates.languages` trỏ tới các bản còn lại. Gồm: trang tĩnh (`/`, `/shop`, `/collections`, `/new-in`, `/about`), danh mục + danh mục con, bộ sưu tập, chi tiết sản phẩm (lấy hết mọi trang API, 100 sp/lần). Có `lastmod` và `<image:image>` (ảnh sản phẩm / bộ sưu tập, để lên Google Images) |
| Robots | `src/app/robots.ts` → `/robots.txt` | Production: cho phép `/`, chặn `/api/` và các đường dẫn riêng tư theo từng ngôn ngữ (`/admin`, `/login`, `/cart`, `/checkout`, `/account`, `/orders`, `/wishlist`, `/unauthorized`); trỏ tới sitemap. **Môi trường Vercel không phải production (preview/dev): chặn toàn bộ `/`** để bản preview không bị index |
| Noindex | layout `(private)` và `(admin)` | `robots: { index: false, follow: false }` — lớp bảo vệ thứ hai ngoài `robots.txt` |
| Open Graph / Twitter (mặc định) | `src/app/[locale]/layout.tsx` | Ảnh `public/brand/brand_og.png` (1200×630), `og:locale` dạng `vi_VN` / `en_US` (lấy từ `LOCALE_LABELS[locale].ogLocale`), alt từ `shared.site.meta.ogAlt` |
| Open Graph / Twitter (từng trang) | `src/i18n/metadata.ts` → `buildSocialMetadata()` | Mọi trang public gọi trong `generateMetadata` (Next **không** merge sâu `openGraph`, nên mỗi trang phải khai báo đủ). Ảnh chia sẻ: sản phẩm → ảnh đầu của sản phẩm; bộ sưu tập → ảnh bộ sưu tập; danh mục / danh mục con → ảnh sản phẩm đầu tiên; còn lại → ảnh thương hiệu. Có `og:site_name`, `og:url`, `og:locale:alternate` |
| JSON-LD | `src/lib/structured-data.ts` + `_components/JsonLd.tsx` | `WebSite` + `Organization` (trang chủ); `BreadcrumbList` (shop, danh mục, danh mục con, sản phẩm, bộ sưu tập, chi tiết bộ sưu tập); `Product` + `Offer` (chi tiết sản phẩm). `JsonLd` escape `<` để dữ liệu không đóng được thẻ script |

Ghi chú vận hành:
- Sitemap có `revalidate = 3600` — sản phẩm/bộ sưu tập mới xuất hiện trong tối đa 1 giờ, không cần deploy lại.
- Mỗi nguồn dữ liệu (danh mục / bộ sưu tập / sản phẩm) lấy bằng `Promise.allSettled`: API lỗi một phần thì sitemap vẫn trả những phần còn lại.
- Sản phẩm thiếu `category` hoặc `subcategory` bị bỏ khỏi sitemap (không dựng được URL chuẩn).
- `lastmod`: API không trả `updatedAt` cho danh mục và `count` của danh mục con không đáng tin, nên `lastmod` của trang chủ / shop / new-in / danh mục / danh mục con lấy theo **sản phẩm mới cập nhật nhất** trong phạm vi đó; `/collections` theo bộ sưu tập mới nhất; trang `about` không có `lastmod`. Danh mục con chưa có sản phẩm nào bị loại khỏi sitemap (trang mỏng).
- `priority` / `changefreq` Google đã bỏ qua; giữ `priority` chỉ để các công cụ khác tham khảo.
- Không chặn `/media/` trong robots: đó là proxy ảnh, chặn sẽ làm Google Images không đọc được ảnh.
- Thêm ngôn ngữ mới: chỉ cần thêm vào `routing.locales` — sitemap, robots, hreflang tự nhận.
- Thêm trang công khai mới: thêm path vào `STATIC_PATHS` trong `sitemap.ts` (trang động thì thêm vòng lặp tương ứng), và dùng `buildAlternates` trong `generateMetadata`. Trang riêng tư mới: thêm path vào `PRIVATE_PATHS` trong `robots.ts`.
- `Product` JSON-LD: giá luôn USD (`price` định dạng `45.00`); API công khai chỉ trả sản phẩm `active` và chưa có tồn kho nên `availability` luôn là `InStock`. Không có `aggregateRating` vì chưa có dữ liệu đánh giá thật ở server — không được bịa.
- Thêm trang public mới: gọi `buildSocialMetadata({ locale, path, title, description, image? })` trong `generateMetadata`, và thêm `<JsonLd data={breadcrumbJsonLd(locale, [...])} />` nếu trang nằm trong cây điều hướng.
- Kiểm tra nhanh: xem nguồn trang (View Source) tìm `application/ld+json`; dán URL production vào Google Rich Results Test và Facebook Sharing Debugger.
- Chưa có: `ItemList` cho trang danh sách sản phẩm, `aggregateRating` / `Review` (cần BE trả dữ liệu đánh giá cho SSR).

## 7. Phần quyền admin (đã sửa cùng đợt)

Thứ tự kiểm tra ở `/admin`: **đăng nhập → quyền admin → quyền của từng trang → mới tới mật khẩu hệ thống**.
- User không đủ quyền thấy màn "Access Denied" ngay, **không bị hỏi mật khẩu**.
- Vào thẳng URL một trang admin mà không có quyền tương ứng (vd `/admin/orders` thiếu `ORDER_ADMIN_VIEW`) cũng bị chặn trước khi hỏi mật khẩu.
- Nút "View" ở trang Users kiểm tra quyền `USER_ADMIN_UPDATE` trước khi mở hộp thoại mật khẩu.

## 8. Việc để sau

- Dịch dữ liệu từ API (tên/mô tả sản phẩm, danh mục…) cần BE lưu theo từng ngôn ngữ — ngoài phạm vi vì không sửa BE.
- Bản dịch tiếng Việt do AI viết — nên để người bản ngữ duyệt trước khi dùng thật (đặc biệt copy thương hiệu ở landing/about).
- Thêm `aggregateRating`/`Review` vào JSON-LD sản phẩm khi BE có dữ liệu đánh giá (xem mục 6).
- Khi số ngôn ngữ tăng (≥ 5), cân nhắc công cụ quản lý bản dịch (Crowdin / Lokalise) đồng bộ với thư mục `src/messages`.
