# 04 — i18n (multi-language) Convention

Stack: **next-intl v4** · locales `vi` (default) · `en` · URL prefix **always** (`/vi/...`, `/en/...`).
Un-prefixed URLs (`/shop`) are redirected to `/vi/shop` by `src/middleware.ts`. The browser language is never used.

> Rule: **code is English, UI text is translated.** No user-facing string is written in a component, constant, or slice —
> it lives in `src/messages/<locale>/**` and is read with `useTranslations` / `getTranslations`.

---

## 1. Message tree (module & role based)

```
src/messages/<locale>/                 ← identical tree for vi / en  (en is the source of truth)
  common.json                          app-wide: actions, orderStatus, role, status, productBadge, addressField, language
  shared/                              used by ≥2 roles (header, footer, feedback dialogs, errors, cart FAB / quick add, site meta)
  auth/        login.json
  public/      landing · about · shop · product · collections · newIn
  private/     account · cart · checkout · orders · wishlist
  admin/
    shell.json  dashboard.json  products.json  categories.json  collections.json
    orders.json  users.json  siteConfig.json  media.json
    components/                        ← shared admin building blocks = their own sub-module
      dataTable.json  formKit.json  imageFields.json  orderDetailPanel.json  guards.json  crud.json
```

Inside a file, nest **page → section → element** (branches, never a flat list):

```json
{
  "page":  { "title": "Products", "count": "{count, plural, one {# product} other {# products}}" },
  "table": { "columns": { "name": "Name" }, "filters": { "status": "Status" }, "sort": { "newest": "Newest" } },
  "form":  { "tabs": { "general": "General" }, "fields": { "name": "Product Name" }, "placeholders": { "name": "e.g. …" } },
  "toast": { "created": "Product created" },
  "confirmDelete": { "title": "Delete product", "message": "Delete \"{name}\"?" }
}
```

Namespace = file path with dots: `src/messages/en/admin/products.json` → `useTranslations("admin.products")`,
deeper: `useTranslations("admin.products.table.columns")`.

**Where does a string go?**
| String is used by… | File |
|---|---|
| one page/module | that module's file (`admin/products.json`) |
| a shared component used by ≥2 modules of one role | `admin/components/<component>.json` (admin) or `shared/<component>.json` |
| ≥2 roles (header, footer, dialogs, errors) | `shared/*.json` |
| everywhere (Cancel, order statuses, roles…) | `common.json` |

## 2. What the client receives

`src/i18n/ScopedMessages.tsx` is used once per route-group layout: the client gets `common + shared + auth + <role>` only
(`public` | `private` | `admin`). Never import another role's namespace in a component (a storefront component must not call
`useTranslations("admin…")`).

## 3. Using it

```tsx
"use client";
import { useFormatter, useTranslations } from "next-intl";

const t = useTranslations("admin.products");
const format = useFormatter();

t("page.title");
t("page.count", { count: total });                 // ICU plural
t.rich("toastAdded", { link: (c) => <Link href="/cart">{c}</Link> });   // markup in a message
const { fmt } = useMoney();                        // src/hooks/use-money.ts — money NEVER goes through format.number
fmt(product, "price");                             // reads priceVnd / priceUsd: VND for vi, USD otherwise
format.dateTime(new Date(iso), "short");           // "short" | "long" | "dateTime" | "monthYear"
```

Server components / metadata (async): `const t = await getTranslations({ locale, namespace: "public.about.meta" })`.
In every **server page/layout** call `setRequestLocale(locale)` first (keeps static rendering / ISR).

Helpers: `useOrderStatusLabel()`, `useRoleLabel()`, `useAddressFieldLabel()` (`src/i18n/use-labels.ts`, fall back to the raw API value),
`errorMessage(err, t("…failed"))` (`src/i18n/error-message.ts`) for toasts, `buildAlternates(locale, "/path")` + `withBrand(title)` for metadata.

### Navigation — always from `@/src/i18n/navigation`
```ts
import { Link, useRouter, usePathname, redirect } from "@/src/i18n/navigation";
```
Never `next/link`, `useRouter/usePathname/redirect` from `next/navigation` (they drop the `/<locale>` prefix).
`useSearchParams`, `useParams`, `notFound` still come from `next/navigation`. Paths are written **without** locale: `href="/shop"`.

## 4. Rules (do not break these)

1. **No hardcoded UI text** — labels, buttons, placeholders, `aria-label`/`title`/`alt`, toasts, confirm dialogs, metadata, error fallbacks.
2. **Never build sentences from fragments** (`"Sign in to " + action`). Use one message per sentence, with `{placeholders}` / `t.rich`.
3. **Plurals via ICU**, never `count === 1 ? "item" : "items"`. **Money via `useMoney()`, dates via `useFormatter`**, never `toFixed` / `toLocaleString`.
4. **Constants hold keys, not labels**: `{ value: "createdAt", key: "newest" }` and translate in the component (`t(\`table.sort.${o.key}\`)`).
5. **Stored values are data, not UI**: sizes (`One Size`), tags, season names, `country: "Vietnam"` stay as-is. API content (product names…) is not translated (BE has no i18n).
6. **Errors thrown by client code carry no text**: `throw new Error("")`; the UI shows `errorMessage(err, t("fallback"))`.
7. A message used in a `useMemo`/`useCallback` must be in its deps (or the memo must depend on `locale`).
8. Keep keys camelCase, values natural sentences; the `en` text is the reference for tone.

## 5. Add / change text

1. Add the key to **`en`**, then the **same key** to every other locale (`vi`). Same `{placeholders}` everywhere.
2. `yarn i18n:sync` (regenerates `src/i18n/registry.ts`; runs automatically before `dev`/`build`).
3. `yarn i18n:check` — fails on: missing file/key, extra key, empty value, different `{placeholders}`, stale registry.
4. `tsc` knows every key (`Messages` type is derived from the `en` JSON) — a typo is a compile error.

## 6. Add a page / module

1. Create `src/messages/{en,vi}/<role>/<module>.json` (+ `meta.title` / `meta.description` for pages).
2. `generateMetadata` → `getTranslations({ locale, namespace: "<role>.<module>.meta" })`, `alternates: buildAlternates(locale, "/path")`, title via `withBrand`.
3. Shared component of an admin module → `admin/components/<name>.json`, not the module file.

## 7. Add a language (e.g. `ja`)

1. `src/i18n/routing.ts`: add `"ja"` to `locales` and an entry in `LOCALE_LABELS` (native name, short code and `ogLocale` such as `ja_JP`).
2. Copy `src/messages/en` → `src/messages/ja` and translate.
3. `yarn i18n:check`. The footer / burger-menu switcher, `hreflang` and routing pick it up automatically — no other code changes.

## 8. Language switcher

`src/app/[locale]/_components/LanguageSwitcher.tsx` (`variant="footer" | "drawer"`) — used in `SiteFooter` and `HamburgerMenu`.
It keeps path + query string and only swaps the locale prefix.

## Docs (mandatory)

This work changes a module, so it is part of the docs loop (`.agent/rules/module-docs.md`, `.agent/skills/07-module-docs.md`):

1. **Before editing** — `yarn docs:who <file|folder|module>`, read the owning doc(s) and the module's code; if they disagree, fix the doc first.
2. **After editing** — update the module doc in the same change (affected sections, `Cập nhật` date) and run `yarn docs:check --changed`. Not done until it passes.
